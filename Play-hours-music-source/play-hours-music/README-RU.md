# Play-hours music

Нативный Flutter-проект для Android, Windows и iOS. Это исходный код приложения, а не сайт и не готовый установщик.

## Статус комплекта

- Написаны интерфейс и логика приложения, серверная схема Supabase, тесты и сценарии сборки.
- Использована исходная третья картинка пользователя: `assets/app-icon.jpg`.
- APK, EXE и подписанный IPA в этот архив НЕ входят. В рабочей среде нет Flutter/Android SDK, Windows toolchain и Xcode; получить Flutter SDK по проверенным адресам не удалось.
- Компиляция, Flutter-тесты, работа на телефоне, воспроизведение и взаимодействие с реальным сервером НЕ проверены. Перед распространением необходимо выполнить приведённые ниже команды и контрольные сценарии.
- Сервер не создан и не подключён. Без параметров сервера приложение честно показывает экран подключения; выдуманных треков нет.

## Что реализовано в исходниках

Главная с квадратными обложками и пустым начальным каталогом. Поиск по названию, артисту и жанру с приблизительным совпадением названий. Круглая кнопка профиля с пунктами «Мои треки», «Загрузить трек», «Мой профиль», «Настройки профиля».

Регистрация и вход по email/паролю. Профиль с именем артиста и описанием. Название песни задаётся при публикации, имя артиста — в профиле; изменение имени отражается у треков.

Загрузка MP3 до 50 МБ, обложки JPG/PNG/WebP до 15 МБ, названия, жанра и текста песни. Текст необязателен для инструментальных треков. Экран обрезки обложки имеет квадратное окно, горизонтальное/вертикальное положение и масштаб; сохраняет JPEG 1024×1024.

Плеер с крупной обложкой, паузой, перемоткой, предыдущим/следующим треком, повтором, лайками, текстом, комментариями и системной кнопкой «Поделиться». Во время перехода между экранами используется один плеер. Мини-плеер остаётся на главной. Кнопка домика доступна на каждом экране.

Каталог, профили, лайки и комментарии хранятся на общем сервере. Чтение доступно без входа; публикации и реакции — после входа. Пользователь может удалить свои треки и свои комментарии. Строковые политики ограничивают изменения владельцем.

## Подключение общего каталога

1. Создать отдельный проект Supabase на https://supabase.com/dashboard.
2. В SQL Editor выполнить `backend/schema.sql` ОДИН РАЗ в новом проекте.
3. В Authentication включить email/password. Если включено подтверждение email, пользователь сначала подтверждает письмо, затем входит вручную. Для публичного использования настроить доставку почты и ограничения запросов.
4. Скопировать `config.example.json` в `config.json`.
5. Указать URL проекта и публичный publishable/anon key из настроек API. **Не использовать service_role/secret key в приложении.**
6. Проверить допустимый размер загрузки Storage: до 50 МБ. Файлы в бакете `music` публичны: это соответствует общему музыкальному каталогу.

Приложение намеренно не содержит паролей, чужих серверных ключей или вымышленного рабочего адреса.

## Сборка с компьютера

Установить Flutter 3.35.4 и SDK целевой платформы. Python 3 нужен для сценариев. Открыть терминал в корне папки проекта:

```sh
python scripts/bootstrap.py
```

Сценарий создаст стандартные проекты Android/iOS/Windows, установит зависимости и сгенерирует иконки из исходной картинки. Затем:

```sh
flutter analyze --no-fatal-infos
flutter test
```

### Android — APK

Нужны Android SDK, JDK 17 и принятые Android SDK licenses:

```sh
python scripts/build.py android
```

Результат: `build/app/outputs/flutter-apk/app-release.apk`.

Созданный Flutter runner по умолчанию подписывает release тестовым debug-ключом. Такая сборка предназначена для проверки/установки вручную. Для распространения и стабильных обновлений настроить собственный постоянный keystore; хранить его отдельно и не терять. Для Google Play потребуется release signing и AAB.

### Windows — EXE

Сборка выполняется на Windows с Visual Studio и компонентом Desktop development with C++:

```sh
python scripts/build.py windows
```

Результат: папка `build/windows/x64/runner/Release/` с `play_hours_music.exe`, DLL и `data`. Передавать пользователю всю папку в ZIP: отдельный EXE без библиотек не заработает. При необходимости установить Microsoft Visual C++ Redistributable x64. Это переносимая папка программы, не отдельный мастер установки.

### iPhone — iOS

Нужен Mac с Xcode. После bootstrap открыть `ios/Runner.xcworkspace`, выбрать свою Apple Team и уникальный Bundle ID. Затем:

```sh
python scripts/build.py ios
```

Результат после корректной подписи: `build/ios/ipa/`. Для распространения через TestFlight/App Store потребуется настроенный Apple Developer/App Store Connect. Без сертификатов нельзя сделать устанавливаемый IPA. APK и EXE на iPhone не устанавливаются.

## Автоматическая сборка без локальной установки Flutter

В комплекте `.github/workflows/build.yml`. Чтобы использовать:

1. Создать свой GitHub-репозиторий и загрузить содержимое этой папки, включая `.github/workflows`.
2. В Settings → Secrets and variables → Actions добавить `SUPABASE_URL` и `SUPABASE_ANON_KEY`.
3. Actions → Build Play-hours music → Run workflow.
4. После успешной проверки скачать артефакты Android и Windows.

Задание iOS только проверяет компиляцию и выдаёт **неподписанный Runner.app, который нельзя установить на iPhone**. Для IPA нужна подпись на Mac или отдельная конфигурация CI с вашими сертификатами. Workflow подготовлен, но в этой сессии не запускался; при первом запуске могут потребоваться исправления совместимости инструментов.

## Контрольные сценарии перед выпуском

- Создать аккаунт A, подтвердить email, задать имя артиста.
- Опубликовать настоящий MP3 с прямоугольной обложкой. Проверить соответствие сохранённой обложки квадратному предпросмотру.
- На другом устройстве/аккаунте B обновить каталог и найти опубликованный трек. Прослушать, перемотать, открыть текст, поставить/снять лайк и написать комментарий.
- Проверить, что B не может через API изменить профиль A или удалить его трек/комментарий/файл.
- Проверить «Мои треки», домик со всех экранов и сохранение профиля после перезапуска.
- Изменить имя артиста: проверить каталог и плеер.
- Проверить ошибки сети, отмену выбора файлов, неподходящие файлы, очень длинные названия и отсутствие текста песни.
- Удалить трек владельцем и проверить, что он исчез у другого пользователя после обновления.

## Границы первой версии

- Обновление каталога/комментариев — при открытии и ручном обновлении, без push и realtime.
- «Поделиться» передаёт название/артиста и прямую рабочую ссылку на MP3, не ссылку на страницу трека внутри приложения.
- Фоновое воспроизведение при блокировке телефона и системные медиакнопки пока не реализованы.
- Профиль — имя артиста и описание; загрузки аватара нет.
- Нет восстановления пароля в интерфейсе, удаления аккаунта в интерфейсе, жалоб, блокировки пользователей, модераторской панели и серверной проверки содержимого MP3. Перед публичным запуском эти функции и требования магазинов следует обработать отдельно.
- Ограничения файла проверяются клиентом; Storage дополнительно ограничивает размер и MIME. Клиентская проверка не заменяет проверку медиаданных на сервере.
- При редкой ошибке удаления/обрыве процесса возможны неиспользуемые файлы в Storage; владельцу сервера нужна периодическая очистка файлов, на которые нет записей tracks.
- SQL миграция рассчитана на новый проект. Для существующего сервера нужна миграция с учётом его данных.
